# 통합 후 남는 확인 사항

## 실제 통화 화면 표시

자동 검증은 권한 거부 및 실제 grant→revoke 이후 helper/notification의 안전한 반환을 검사한다. `showInCallScreen()`의 true는 Telecom API 정상 반환이며 화면 표시 증거가 아니다. 통화 중 실제 전화 앱 표시와 overlay 상호작용은 아래 조건에서 사람이 확인한다.

1. 앱 설치/권한/overlay 상태가 확인된 전화 기기에서 사용자가 명시적으로 시작한 비긴급 테스트 통화만 사용한다. 상대방 동의 없이 녹음·개인정보 수집을 하지 않는다. 자동 발신·자동 종료는 하지 않는다.
2. 승인된 테스트 상황에서 통화 중 경고 overlay의 “전화 앱으로 이동”을 사용자가 누른다. 전화 UI가 실제 표시되는지, 기존 지연 후 해당 overlay만 닫히는지, 새 경고가 생기면 이전 지연 콜백이 새 overlay를 닫지 않는지 관찰한다.
3. OS 설정에서 전화 권한을 철회하고 재진입했을 때 앱이 중단되지 않는지 확인한다. OS가 권한 변경으로 프로세스를 종료한 결과와 앱 예외에 의한 크래시를 구분한다. 안전 확인/session 종료 동작이 자동 실행됐다고 추정하지 않는다.
4. 기기/API/앱 커밋, 사용자가 실행한 절차, 화면 관찰 결과를 기록한다. 전화번호·통화 내용은 기록하지 않는다.

현재 자동 검증에 실제 통화 화면 표시, API 실행 도중 권한 철회 타이밍, 여러 OEM 동작이 포함됐다고 표시하지 않는다. 본 작업은 통화를 시작하거나 이 수동 항목을 완료 처리하지 않는다.

## 통합 PR과 병합 순서

기존 #10(M2), #11(권한), #12(M3)는 보존한다. integration branch는 #11과 #12의 결합 및 추가 검증 증거다. main 병합 승인 전까지 어느 PR도 main에 병합하지 않는다. 병합 승인이 생기면 M2 기준선 반영, 최종 채택할 통합 경로 결정, base 변경 후 새 HEAD 확인 순서로 진행한다. 이미 포함된 변경을 중복 cherry-pick하지 않는다.

## CI 후속 범위

GitHub 자동 체크 미설정은 로컬 검증과 별개다. 후속 CI 설계에서는 unit555, build/kapt/duplicate, exact lint union 및 instrumentation17을 분리하고 JDK21/SDK34를 고정한다. 새 workflow 파일과 원격 runner/권한 설정을 결정한 뒤 도입한다. secrets나 실제 전화기 없이 실행 가능한 기본 검증부터 구성하고, 실제 통화 UI는 수동으로 유지한다. 이번 통합 검증에 CI 도입이 포함됐다고 주장하지 않는다.
